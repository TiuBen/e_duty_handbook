# 2026-08-23 工作日志

## 搭建 VoiceRec 本地 ASR 服务（SenseVoice Small + Node.js/Express）

在 `VoiceRec/` 目录完成本地语音识别服务的完整搭建与端到端验证。

### 技术选型
- **纯 Node.js 方案**：`sherpa-onnx-node`（官方 npm 包，Windows x64 有预编译绑定 `sherpa-onnx-win-x64`），绕开 Python/PyTorch/funasr 的重量级依赖。
- 模型：SenseVoice Small ONNX 版 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17`（model.int8.onnx 229MB + tokens.txt，多语言：中/英/日/韩/粤，附带情感与音频事件检测）。

### 关键坑与解决
1. **GitHub 下载超慢/失败** → 改用 **ModelScope 国内镜像** `poloniumrock/SenseVoiceSmallOnnx`（~4MB/s），下载脚本支持多镜像自动回退。
2. **Windows 端口保留段**：`netsh interface ipv4 show excludedportrange protocol=tcp` 显示 5184-5283 被 Hyper-V/WinNAT 保留，监听报 EACCES。默认端口从 5184 改为 **5300**（不在保留段），并在 server.js 加 listen error 友好提示。
3. **进程残留问题**：bash 后台 node 进程常被杀不干净，测试时 curl 打到旧进程。统一用 PowerShell `Get-NetTCPConnection` + `Stop-Process` 精确清理。
4. sherpa-onnx 返回的 lang/emotion/event 带 `<|zh|>` 富文本标签 → 用 `extractTag` 提取标签内容。

### 架构
`server.js` 入口 → `src/app.js` → routes/controllers/services/utils 分层。核心：
- `recognizer.service.js`：OfflineRecognizer 单例懒加载，`transcribe(samples, sampleRate)` 接口，失败不阻塞启动。
- `audio.service.js`：wav 直读（sherpa_onnx.readWave）+ 其他格式 ffmpeg 转码兜底（本机已有 ffmpeg 8.1.2）。
- API：`GET /api/asr/health`、`POST /api/asr/transcribe`（multipart 字段 audio，≤20MB）。

### 验证结果
- 5.62s 中文音频（zh.mp3，SenseVoice 官方示例"开饭时间早上九点至下午五点"）识别 **~200ms**，lang=zh 正确。
- mp3（ffmpeg 转码）与 wav（直读）两条路径均通过。

### 其他
- 本机 node v22.22.2、npm 10.9.7、ffmpeg 8.1.2 可用；pnpm 未装（用 npm）。
- 测试音频 test-audio/zh.mp3（SenseVoice 官方）已保留。
