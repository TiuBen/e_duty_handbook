### 经验沉淀
- 用户给"草稿"类需求时，先确认 **平台形态 + 屏幕方向**（手机竖/横、平板竖/横、桌面）再画布局，避免做完返工
- 用户说"2 个悬浮框"但列了 3 个名字时，要理解为"3 选 2"——当前界面对应的不显示，只显示另外 2 个
- "不需要显示 X"的反馈往往意味着精简信息密度，不只是删某个元素，还要重新审视是否还有同类冗余
- "胶囊 vs 半圆矩形"的差异要敏感：胶囊=两端都是半圆，半圆矩形=只有一端半圆（书签标签），常用于吸附边缘的设计
- 贴边吸附的可拖拽组件要：mousedown 改定位模式 → mousemove 跟随 → mouseup snapToEdge（计算到边缘距离最近）
- 删除 DOM 元素时务必 grep 同名 id 在 JS 里的引用，一并清理，否则运行时 null.textContent 报错
- **导航按钮颜色不要用主/次区分**：用户会把"蓝色按钮"误解为"当前所在页面"。多个同级导航按钮应统一颜色，当前页面用其他方式（如水印）标识
- **悬浮组件 ≠ 占位组件**：absolute 定位的悬浮元素不需要给主内容让 padding，让它真正浮在上层；用户明确说"不占空间"时不要自作主张加避让 padding
- **水印设计**：淡色（rgba 6%）、大字（96px）、斜体（rotate -18°）；"在最前面"= z-index 最高，"无交互"= pointer-events: none；这两者结合才是合格的水印（视觉装饰但点击穿透）
- **页面语义要听用户原文命名**：用户说"我的交接班页面是你当前的检查单页面"——意思是用户对页面有自己的命名习惯（"交接班"=逐项确认检查单），不能用开发者的命名去套用户的语义
