## 🔴 特殊页「1 条台账渲染 3 列」根因：快照级 is_fresh + 腿行日期全 null
- 现场：records_special 只有 1 行（#41 O37078 / ecyilang_uuid 4f9ebae2…），特殊页却渲染 3 列
  （O37078 ×2 + O36805）。该快照 **a 腿=O36805（进港）/ d 腿=O37078（离港）**。
- 根因 1（两个 O37078 之一 + O36805）：`toApi` 的 is_fresh 是**快照级**（取最新一条台账 freshMark），
  `ecyilangToFips` 把这个布尔原样复制给两条腿 → 一条腿被标，两条腿都算生鲜。
  修：`LINK_INCLUDE.specials` 去掉 `take:1` 改取**全部**（select callsign + nodes），
  `toApi` 额外输出 **`fresh_callsigns`**（freshMark 为真的 callsign 数组）；
  `ecyilangToFips` 用新导出的 **`legIsFresh(callsigns, 腿航班号)`** 逐腿判定（精确 + 数字后缀兜底，
  兼容历史 ICAO 形态 CSS37078 ↔ O37078）→ 腿级 `is_fresh`，未标的那条 `fresh_content` 也置 null。
- 根因 2（第三个 = 台账又补一列）：`mergePageRows` 去重键 = 航班号+日期，而腿行**没有日期** →
  `dateKeyOf` 返空串 → 与台账 `createdDate` 对不上 → 重复补行。
  修：`specialStore.dateKeyOf` 加 **`flight.mapped_date` / `flight.flight_date`**（ecyilang 的
  a/d_flight_date 通过 ecyilangToFips 映射到 mapped_date）；`mergePageRows` 再加一条兜底：
  航班源存在「同航班号且无日期」的行时，台账不再补列。
- 🔴 根因 3（顺带挖出的真 bug，影响面更大）：`ecyilangToFips` 的 `pick()` 用
  `typeof value === 'object'` 剥对象变体 —— **Date 也是 object** → `row.d_flight_date` /
  `d_plan_time` / `created_at` 全被剥成 null。所以 fips 形状的 ecyilang 腿行**日期和时间列一直是空的**
  （mapped_date / sobt / aldt 全 null）。修：`&& !(value instanceof Date)`。
  修完 sobt 等时间列才有值（'2026-10-28 05:35'），特殊页日期过滤 / 日历徽标也跟着正确。
- 实测：特殊页 1 架 O37078（O36805 不出现）；再用 API 临时给 a 腿建台账 → 2 架（O37078 + O36805，无重复）
  → 删除临时行复原；fips 页角标 1 / Leaf 1（只 d 腿）/ 只看生鲜 2 行（整快照的到+离）；0 报错。
