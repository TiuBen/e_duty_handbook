### 踩到的坑（下次直接照抄结论）
1. **Prisma 7 的 `prisma-client` 生成器只产 TypeScript**（`generatedFileExtension` 仅 ts/mts/cts），

2. **seed 命令由 shell 执行，PATH 里没有 `node_modules/.bin`**。
   第一次写 `seed: 'tsx prisma/seed.ts'` 直接报「'tsx' 不是内部或外部命令」→ 改成 `pnpm exec tsx ...` 才通。
3. Prisma 7 起 seed 只在显式 `prisma db seed` 时触发，不再随 migrate dev / reset 自动跑。

Prisma 自动生成的版本是 **DROP TABLE + CREATE TABLE**（数据全丢），必须替换。

**索引/约束的坑**：PostgreSQL 的 `ALTER TABLE ... RENAME TO` **不会**连带重命名索引与约束（18.3 已用临时表实测验证）。
但对 PK / UNIQUE 约束**底层**的索引执行 `ALTER INDEX ... RENAME`，约束名会同步跟着改，不必再 RENAME CONSTRAINT。
NOT NULL 约束不是索引，只能 `ALTER TABLE ... RENAME CONSTRAINT`（无 IF EXISTS 可加）。

最终名字：`records_checklist_pkey` / `idx_records_checklist_flight_uuid` / `idx_records_checklist_flight_date`；
`records_special_pkey` / `records_special_callsign_belong_key` / `idx_records_special_belong_time` / `idx_records_special_flight_uuid`；
NOT NULL 约束同理换前缀。

### 🔴 两个必须记住的坑

**坑 1：`prisma db push` 会把「重命名」当成 DROP + CREATE。**
- 表里有数据 → 直接报错，要求 `--accept-data-loss`（**这是好事，会拦你**）。
- 表是空的时候 → **静默删表重建**，什么警告都不打（输出只说 "Your database is now in sync"）。
- 所以**表改名绝不能靠 db push**，一定要走 migrate + 手写 ALTER RENAME。
  （这次排查时我自己就在临时库上踩了一次：push 把空表悄悄重建 → 随后回放改名迁移报 `关系 checklist_records 不存在`，
   一度误以为是迁移写错了。）

**坑 2：`0_init/migration.sql` 里 pg_dump 带的 `set_config('search_path', '', false)` 会毁掉 Prisma 迁移机制。**
- 它把会话 search_path 清空，而 Prisma 在同一会话里跑迁移并提交，这个设置会一直留着 →
  迁移跑完 Prisma 找不到自己的 `_prisma_migrations`，报 `P1014`；影子库回放失败 → `migrate dev` 误报「整库都是 drift」。
- 已改成 `set_config('search_path', 'public', false)`（文件里其余对象本来就是 `public.` 全限定名，不受影响）。
- 顺带修正了一个认知：`_prisma_migrations` 曾被 `migrate dev` 的失败回放搞得没了踪影，
  排查确认 **`db push` 不会删它**（临时库实测）。基线已重新 `migrate resolve --applied 0_init` 固化。

### ⚠️ 最重要的坑：Prisma 读 timestamptz 会整体差 8 小时
实测（PG 会话时区 Asia/Shanghai）：
| 来源 | `manual_fips.created_at` |
|---|---|
| 库里真值 | `2026-08-30 14:23:51.271+08` = `06:23:51Z` |
| 不设 UTC 的 Prisma | `2026-08-30T14:23:51.271Z` ❌ 把本地墙上时间当成 UTC |
| node-postgres（旧 raw SQL） | `2026-08-30T06:23:51.271Z` ✅ |
| **设 UTC 后的 Prisma** | `2026-08-30T06:23:51.271Z` ✅ |
原因：PG 按会话时区渲染 timestamptz（带 `+08`），Prisma 的 pg driver adapter 不认这个偏移量。

**修法（已固化）**：`new PrismaPg({ connectionString, options: '-c TimeZone=UTC' })`，写在 `prismaFactory.js`。
影响面：`manual_fips.created_at`、`ecyilang.created_at`、`records_checklist.created_at/updated_at`；
前端 manual 列表的「按日期筛选」就是拿 created_at 现算本地日，差 8 小时会让 16:00 后录入的航班算到第二天；
后端检查单 24h 锁定也会晚锁 8 小时。**换 ORM 才会暴露，务必记住这条**。

### Prisma 表达不了、改用 JS 顶上的三处（都写了注释说明为什么等价）
1. `ecyilang` 过滤 `COALESCE(LEFT(d_flight_date,10), LEFT(a_flight_date,10))`
