## 应要求把原 server/ 恢复到 temp/server

**需求**：把「被删掉的 server 项目」恢复到 `temp/` 下。

**关键事实（后续排查可复用）**：`server/` 绝大部分内容其实**不是被删而是被 mv 走了**（在 `voice-record-recalibrate-server/` 里完好）。真正进回收站的只有 `public/`（旧前端）与 9/7、9/11 用户自行清理的历史文件（`models/*.tar.bz2` 归档、streaming-zipformer 旧模型、其他平台 sherpa-onnx 二进制、tmp wav）。判定依据：解析 `D:\$RECYCLE.BIN\<SID>\$I*` 元数据（v2 格式：offset 8=大小、16=FILETIME 删除时间、24=路径长度、28 起 UTF-16LE 原路径）。

**做法**：`cp -a voice-record-recalibrate-server/. temp/server/` → 再从回收站 `$R0O4GVQ.js`→`public/admin.js`、`$R2GEKSH.html`→`public/index.html` 还原（与备份 `D:/GitHub/_backup_server_public_20260924/` sha256 一致，时间戳保留 Sep 11，确为原件）。

**结果**：`temp/server` 736M（src 40K / scripts 12K / models 707M / uploads 1.7M / node_modules 27M / public 44K）。校验 = 源 95 文件全部在位无缺失、大小无差异，+2 个还原的 public 文件；`samples.json` 23 条 ↔ `uploads/` 23 个 wav，无 orphan 音频。

**注意**：`temp/server` 里 `package.json`、`README.md`、`src/index.js` 是**迁移后被改过的版本**（name 已改、`/admin` 静态托管已移除、README 重写），不是拆分前的原始内容；`public/` 与数据文件则是原始件。

**回收站解析技巧**：`$I` 与 `$R` 成对，`$I` 存元数据、`$R` 存实体；删除文件夹时 `$R` 目录可能为空壳，文件被单独登记在回收站根（本例即如此）。Bash 读该路径要用单引号 `/d/'$RECYCLE.BIN'/...` 防变量展开。
