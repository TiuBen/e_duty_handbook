## 切换 SenseVoice 模型（识别效果差 → SenseVoice int8）
- 用户反馈 zipformer-small-bilingual 中文识别差。切换到官方 SenseVoice int8 最新版：`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09.tar.bz2`（158MB，fp32 版 845MB+ 太大不用）；用 `MODEL_URL=... MODEL_TYPE=sense-voice node scripts/download-model.js` 下载，model-config.json 自动切为 sense-voice（旧 zipformer 模型目录保留 437MB 可手动删）。
- 坑：sherpa-onnx-node OfflineRecognizer 的 getResult(stream) 返回**对象** `{lang, emotion, event, text, timestamps,...}` 而不是数组！原 `result[0].text` 恒为空 → 识别结果空白。改为取 `result.text`，并用正则剥离 `<|zh|>` `<|NEUTRAL|>` 等标签。OnlineRecognizer（zipformer）的 getResult 则返回 `{text}`。
- OfflineModelConfig.senseVoice = { model, language, useInverseTextNormalization }；language 设 'zh'。
- 新增 scripts/test-asr.js 冒烟自检：加载模型 + 识别 wav（默认用模型包自带 test_wavs/zh.wav 真实人声），不占 HTTP 端口。实测 zh.wav 5.59s→0.12s 识别"开放时间早上九点至下午五点"，速度与正确率远好于 zipformer。
- 经验：sherpa-onnx 模型 tar 包内自带 test_wavs/*.wav，可作真实人声离线验证素材（无需 TTS）。
- 模型切换后需重启 npm start 生效（asr.js 进程内单例启动时加载）。
