## V5-dispatch：独立部署检查（能不能「复制 + npm install 就跑」）
**结论：原来不能，已修好。** 三个拦路虎：
1. 🔴 `package.json` 里 `@prisma/adapter-pg` / `@prisma/client` / `prisma` 写的是 **`catalog:prisma`**
   —— pnpm workspace 专有协议，**npm 直接 `EUNSUPPORTEDPROTOCOL: Unsupported URL Type "catalog:"` 装不下去**
   （已用独立目录真实复现）。→ 改成写死 `7.3.0`。
2. `engines.node` 写的 `>=18` 是错的：**Prisma 7.3.0 实际要求 `^20.19 || ^22.12 || >=24.0`** → 已对齐。
3. `prisma/generated/` 是 **gitignore 的产物**（且生成的是 `.ts` 源码，必须 tsx 跑）→ 补 `"postinstall": "prisma generate"`，
   这样 `npm install` 一步就能把客户端生成出来。
- **独立目录实测链路**：`npm install --ignore-scripts` → `npx prisma generate` ✔ → `PORT=5199 tsx server.js` ✔
  → `/api/health` ok、`/api/fips?source=ecyilang&date=2026-10-11` total=115、`/api/setting/airports` total=74。
  完整 `npm install`（带脚本）在本沙箱里卡在 **esbuild 的 install.js spawnSync EBUSY**（沙箱不让 spawn 那个 node.exe），
  **是本机沙箱限制、不是项目问题**，服务器上不会遇到。
- ⚠️ **`.env` 是必需的**：`prisma.config.mjs` 用 `env("DATABASE_URL")`，**缺 .env 时 `prisma generate` 直接
  `PrismaConfigEnvError`** → postinstall 会连带失败。复制时要么带上（它在 git 里），要么先在服务器建好。
- ⚠️ git 里还**留着旧的 `prisma/migrations/0_init/migration.sql`**（磁盘上已删，内容是老版本的 4 个自定义函数 + pgcrypto）
