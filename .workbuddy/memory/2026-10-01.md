## V5-dispatch：fresh_air_cargo 泛化为跨来源生鲜标记表

**需求**：`fresh_air_cargo.manual_fips_id` 改成 UUID，并新增 `source_table`。
经确认：**用 PG 原生 `uuid` 类型**，且**列名改为 `source_id`**。

### 新结构（业务自然键 = source_table + source_id）
`id SERIAL PK` / `source_table VARCHAR(32) NOT NULL DEFAULT 'manual_fips'` /
`source_id UUID NOT NULL` / `content JSONB` / `created_at TIMESTAMPTZ`，
唯一索引 `fresh_air_cargo_source_key(source_table, source_id)`，**外键已去掉**（多来源无法指向单表）。

### 迁移（`src/db/schema.js` 新增 `ensureFreshAirCargo(p)`）
`manual_fips_id INTEGER UNIQUE + FK ... ON DELETE CASCADE` → `source_id UUID`：
加 `source_table` → 加可空 `source_id` → 用 `manual_fips.uuid` 回填（带 UUID 正则过滤防脏数据打断启动）
→ 丢弃回填不到的孤儿行 → 拆旧约束 → 删旧列 → `SET NOT NULL` → 建唯一索引。幂等可续跑。

**关键踩坑**：旧列上的 UNIQUE 是**约束**（`fresh_air_cargo_manual_fips_id_key`）不是裸索引，
`DROP INDEX` 会被 PG 拒（`cannot drop index ... because constraint ... requires it`），
导致迁移**跑到一半中断**（列已加、数据已回填，但旧列/旧索引还在）。改成
`ALTER TABLE ... DROP CONSTRAINT IF EXISTS` 后重跑即通（幂等设计正好从中断处恢复）。

### 连带影响（都改了）
- 去掉外键 → 级联删除消失：`manualFipsService.deleteManualFips()` 改为显式删该航班的生鲜标记。
- `listManualFips()` 的 JOIN 改成 `f.source_table='manual_fips' AND f.source_id::text = m.uuid`
  （UUID 列 vs VARCHAR 列按**文本**比，避免脏数据 `::uuid` 报错）。
- `freshAirCargoService.listFresh()` 改 LEFT JOIN（非 manual_fips 来源也要能列出，航班字段为 null）。
- 接口签名：`POST /mark {sourceId, sourceTable?, content?}`、`DELETE /mark/:sourceId?sourceTable=`；
  controller 加 UUID 正则校验（非法 → 400，而不是让 PG 抛 500）。
- 前端 `api/index.js` 的 `freshAirCargoApi.mark/unmark(sourceId, content, sourceTable)`；
  `FipsPage` 三处改为传 `row.uuid`（原来传自增 `selectedId`）。
- `data/schema.sql`（早期 dump 快照）同步这 3 处，FK 段替换为说明注释。
