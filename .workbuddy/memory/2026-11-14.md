## 🔴 `Unknown argument 'a_plane'` = 远程接口多字段 + 灌库全量透传
- 报错 "Did you mean `a_name`?" 直接指向 **ecyilang** 模型（有 a_name、没有 a_plane）。
  库里 / schema 里都**没有** a_plane 列，代码里也没有这个字面量 → 唯一可能是**运行时动态键**。
- 根因：`db_seed/ecyilangRow.js` 的 `toEcyilangRow` 是 `for (const [k,v] of Object.entries(raw))`
  **全量透传** remote 行的键。远程机场接口今天多了个 `a_plane`（看着像机型），
  整个 data 里就多一个 Prisma 不认识的键 → createMany/create 全批报错：
  00:01 建基线、每 15 分钟增量插入、db_seed 导入、replay 回放全部一起废。
- 修复（**灌库白名单**）：`ecyilangRow.js` 新增 `DB_COLUMNS`（24 列逐条枚举，与 schema 的
  model ecyilang 对齐），`toEcyilangRow` 只搬白名单里的键，白名单外的记进
  **`stats.unknown`（Set）**；三处调用方打印/告警：
  `addNewEcyilangToDb.js` 与 `db_seed.js` 末尾打印被忽略字段；
  `monitorService.toDbRow` 用模块级 `reportedUnknownKeys` 去重，**每个新键只 warn 一次**
  （否则每 15 分钟刷屏）。
- 顺带确认**比对路径安全**：`fieldDiff` 只遍历 `WATCH_FIELDS`（17 个固定字段），
  `patch` 的键必是其中子集 → a_plane 进不了 update；changelog 存整条 raw（Json 列，任意结构）也不报错。
- 验证：探针喂带 `a_plane` + `some_future_field` 的行 → 两者都被忽略、产出键 27 个全在白名单内；
  真实快照 ecyilang202610151741/0009（70/68 行，23 个原始键）→ **0 个被忽略、每行 27 键**（无漏列误伤）；
  时间解析回归正常（`00:30(+1)` → 次日 00:30）；后端 /api/health 200。
- ⚠️ schema 加列时必须同步 `DB_COLUMNS`，漏了不会静默丢 —— 会进 stats.unknown 被打印出来。
